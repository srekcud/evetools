## 6. Choix figés au-delà de la spec

1. **Planner** : `plan()` rend une `list<MiningPlannedPayment>` (VO `position`, `kind`, `payerPosition`, `beneficiaryPosition`, `amount`, `null` = corporation).
2. **Entités** : `MiningPayment::__construct(operation, position, kind, payerMember, payerName, beneficiaryMember, beneficiaryName, float amount)`, `markPaid(User, ?string, \DateTimeImmutable)`, `isPaid()`. `MiningOperation::settle(\DateTimeImmutable, ?string)`, `complete(\DateTimeImmutable, ?\DateTimeImmutable, array $unitPrices, array $minedValues, ?string)`, `getPayments()` (collection modifiable, le harnais y ajoute les lignes), `getArchivedAt()`, `getArchivedByName()`.
3. **Freezer** : `complete(MiningOperation, User $completedBy)` ; messages T3-T6 dans l'ordre de R14.
4. **R7 dans le provider** : `MiningPaymentItemProvider` (PATCH) contrôle l'accès (participation, puis payeur, Owner ou Admin) avant la validation (403 avant 422) ; le processor ne contrôle que le statut (R8) et l'écriture via `MiningOperationSettlement`. Le paiement est retrouvé dans `MiningOperation::getPayments()`, pas de `MiningPaymentRepository` exigé par les tests.
5. **Signatures** : `UpdateMiningPaymentProcessor(Security, MiningOperationRepository, MiningOperationSettlement, MiningOperationResourceMapper, MercurePublisherService)` ; `Settle…Processor` et `Complete…Processor (Security, MiningOperationRepository, MiningOperationAccess, MiningOperationSettlement | MiningShareFreezer, MiningOperationResourceMapper, MercurePublisherService)` ; `MiningPayment{Item,Collection}Provider(Security, MiningOperationRepository, MiningOperationAccess, MiningOperationResourceMapper)` ; `ArchivedMiningOperationsProvider(Security, MiningOperationRepository, MiningOperationArchive, MiningOperationResourceMapper)` ; `MiningOperationSettlement(EntityManagerInterface, ClockInterface)` ; `MiningOperationArchive(MiningShareCalculator)`. `MiningOperationResourceMapper` reste sans dépendance.
6. **`archiveSummary`** : tableau `{archivedAt (chaîne ATOM UTC), archivedByName, totalValue, myMinedValue, myShare, paymentsCount, paidPaymentsCount}` dans cet ordre ; `myShare` du booster = sa part seule (150 en G1), sans la part du booster. Testé sur `GET …/archive` seulement.
7. **Audience** des trois nouveaux événements : testée avec Aria, Brann, Cyra (aucun membre en attente), compatible avec `userIdsOf()` et `participantIdsOf()`.
8. **Corporation de la ligne collectée** : nom tiré de `Character::getCorporationName()` du personnage principal de l'Owner.
9. **Repères DOM du front** : carte = `section` dont le `h2` porte le titre (« Payments », « Mark settled », « Mark completed », « Summary ») ; case à cocher = `input[type=checkbox]` dont l'`aria-label` est `payments.markLabel` ; KPI = `dl > div` avec `dd` dont une classe contient `amber` (reste) ou `emerald` (tout payé) ; étape faite = classe `text-emerald-300` (même jeu que `STATE_CLASS.done`), la dernière étape atteinte est faite et `aria-current="step"` ; archive = lignes `tr`, nom tronqué avec `title` et `truncate`.
10. **Dates du front** : les tests ne figent que l'heure (`at 22:24`, `23:35 EVE`) et le début des phrases ; le format de date est laissé à l'implémentation (l'existant écrit `2026-11-05`, la spec montre `05/11`).
11. **Débiteur au front** : la ligne est cochable par un membre quand `payerMemberId` est sa membership (déduite de `store.members` et des personnages de l'utilisateur, comme `ownMemberId`).
12. **Liste temps réel** : la liste suit `getMiningOperationEvent(id)` des opérations affichées et recharge « Mes opérations » et l'archive une fois chacune sur `operation_settled` ou `operation_completed`.
13. **Montants** : `amount` de la ressource est un entier ; l'entité garde un `float` (comme `MiningFrozenMinedValue`).
