# #301, phase rouge : corrections de projets en console sans nom libre ni message brut

Branche `fix/group-production-tree`, aucun changement dans `src/`.

## Règle proposée (à valider par Sylvain)

1. **Libellé** de l'outcome = nom SDE du type produit (`IndustryCalculationService::resolveTypeName($project->getProductTypeId())`), repli `UnknownTypeName::label()`. Jamais `IndustryProject::getName()`.
   - Ne PAS modifier `getProjectDisplayName()` : l'API (`IndustryResourceMapper`) l'utilise et `IndustryCalculationTest` (l. 300-323) fige son comportement « nom libre d'abord ».
2. **Raison d'un échec venant d'une exception** (`ProjectByProjectCorrection::correctProjects`, branche `catch`) :
   - classe déclarée sous `App\` **ou** classe native PHP (namespace global : `LogicException`, `RuntimeException`, ...) → `<FQCN>: <message>`, message coupé à **200 caractères** puis suffixé `...` (200 caractères exactement : gardé entier) ;
   - toute autre classe (Doctrine DBAL/ORM, vendor) → `<FQCN>` seul, message jamais affiché (un message DBAL 4 contient le SQLSTATE et le `DETAIL` PostgreSQL avec les valeurs).
   - `::class` sans backslash initial, donc `LogicException: A project owner read from the database has no identifier`, `App\Exception\TypeMissingFromSdeException: Types missing from the SDE: 17889`, `Doctrine\DBAL\Exception\DeadlockException`.
   - Raisons construites par l'application sans exception (`No Jita nor structure sell price ...`, `not processed: ...`, `ME/TE would change ...`) : inchangées.
3. `ProjectCorrectionConsoleReport` : **aucun changement nécessaire**. Il imprime `projectId`, `label`, `runs` et `reason` de l'outcome tels quels ; le nom libre et le message brut y arrivent par `ProjectByProjectCorrection`. Pas de test rouge possible sur le rapport sans dupliquer la règle à deux endroits. Les tests des trois commandes (`tests/Unit/Command/{RegenerateMultiUnitSteps,RecalculateReactionSellPrices,ResetReactionMeLevels}CommandTest.php`) passent des outcomes déjà formés : non modifiés, toujours verts.

Limite connue : une exception native levée par un vendor avec un message sensible serait affichée (bornée). Doctrine lève ses propres classes ; `\PDOException` brute n'apparaît pas (DBAL 4 l'enveloppe). Pas de cas de `\PDOException` dans `src/`.
