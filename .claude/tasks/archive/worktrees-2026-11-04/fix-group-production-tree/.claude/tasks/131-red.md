# #131 — phase rouge (jobs en trop d'un groupe découpé)

Spec : `docs/specs/131-split-group-surplus-jobs.md`. Rien n'est commité. `.claude/state/tdd-phase` n'est pas écrit (à faire par l'orchestrateur après validation).

## Squelette créé dans `src/` (signalé)

`applyNeedToSteps()` doit remonter les jobs en trop aux appelants : il renvoie désormais un `AppliedNeed`, sans changement de comportement.

- `src/Service/Industry/AppliedNeed.php` (nouveau) : `final readonly`, `public array $changedSteps`, `public array $surplusJobs`.
- `SplitGroupQuantities::applyNeedToSteps()` renvoie `new AppliedNeed(<ancienne liste>, [])` ; l'ancien corps est passé dans `changedStepsOfTheNeed()` (privée).
- Appelants adaptés mécaniquement (`->changedSteps`) : `IndustryStepCalculator::recalculateStepQuantities()` et `SplitGroupMaterialNeeds::applyChangeOfJobs()`. `IndustryProjectFactory::jobsKeepingFixedRuns()` ignore la valeur de retour et n'est pas modifié.

Choix pour la phase verte : l'absorption (R4, `IndustryProjectStep::absorb()`) est attendue **dans** `applyNeedToSteps()`, parce que U5 vérifie les jobs matchés et le stock au niveau de `SplitGroupQuantities`. Les appelants n'ont qu'à retirer `surplusJobs` de `IndustryProject::getSteps()` (`orphanRemoval`), avec `remove()` si besoin. La note non normative de la spec (« les appelants absorbent ») est donc resserrée.
