# #202 Q1 — phase rouge (refus O1 : étape de matériau sans autre consommateur)

Spec : `docs/specs/202-q1-refuse-deleting-the-only-step-of-a-consumed-product.md` (option A). Circuit m. Aucun changement dans `src/`.

## Résultat

- Fichiers ciblés (`IndustryProjectRefusalToDeleteStepTest|DeleteStepProcessorTest|IndustryResourceMapperDeletableStepTest`) : 65 tests, 10 rouges, 55 verts.
- Suite `tests/Unit` complète : 14 422 tests, 10 échecs (exactement les 10 rouges ci-dessous), 1 incomplet préexistant (`InstallCostTest` D11a), notices PHPUnit préexistantes (mocks sans attente dans `IndustryProjectFactoryTest::setUp`).
- Tous les rouges échouent sur une assertion métier (refus attendu non levé, `null` au lieu du message O1, `deletable` à `true`, attente d'appel 0 au lieu de 1). Aucune erreur de construction.

## Contrats imposés à la phase verte (à valider)

1. **`IndustryProject::refusalToDeleteStep(IndustryProjectStep $step, \Closure $materialTypeIdsOf): ?string`**, signature de la note non normative de la spec. `$materialTypeIdsOf(IndustryProjectStep): list<int>` rend les types de matériaux SDE de l'étape (liste brute, types sans étape compris) ; l'entité filtre elle-même les étapes de production. Aujourd'hui le second argument est ignoré par PHP, d'où un échec propre sur l'assertion. Si une autre forme est préférée, `tests/Unit/Entity/IndustryProjectRefusalToDeleteStepTest.php` est à revoir avant le verrouillage.
2. **`DeleteStepProcessor`** et **`IndustryResourceMapper`** reçoivent une source des matériaux SDE. Les harnais fournissent un `IndustryActivityMaterialRepository` et construisent par type (`AutowiresByType`) : la position du paramètre est libre, et un service de `App\Service\Industry` construit à partir de ce repository est aussi résolu (récursion du trait).
3. **O6 mapper** : `findMaterialEntitiesForBlueprints()` appelée exactement une fois pour trois `stepToResource()` du même projet sur une même instance de mapper.
