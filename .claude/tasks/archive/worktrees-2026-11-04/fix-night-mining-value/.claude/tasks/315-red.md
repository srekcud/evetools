## Contrat figé (choix faits là où la spec se tait)

- Ligne minéral : `typeId, typeName, producedQuantity, deficit, hasDeficit, coveragePercent, coversWholeDeficit, coverageUnknownReason` (ordre des clés libre, valeurs exactes).
- `coversWholeDeficit` : `null` quand `producedQuantity` est inconnu (rendement ou portion), `false` sans déficit, sinon `producedQuantity ≥ deficit`.
- `coverageUnknownReason` : `portion_size_unknown` seulement ; `null` quand c'est le rendement qui manque (porté par `yieldKnown`).
- Un minéral reçu d'un type à portion inconnue est inconnu en entier, même si un autre type le produit aussi (Pyerite de Scordite + Omber).
- Ligne de `shoppingList` à déficit 0 = pas de déficit (pas de division par zéro).
- En `measuring`/`unknown`, `yieldKnown`/`reprocessYield` restent ceux du profil.
- Profil lu par `ReprocessingProfileRepository::findOneBy(['user' => $user])` (comme `ReprocessingProfileProvider`).
- `operationId` = UUID RFC 4122 de l'opération du membre.
- Front : `data-stockpile-coverage`, lignes `data-coverage-mineral="<typeId>"` + `data-coverage-state` ∈ `partial|whole|no-deficit|unknown`, `data-coverage-mineral-name` (title = nom complet), `data-produced-quantity`, `data-coverage-percent` (`56.65%`/`100 %`, `—` si null, absent sans déficit), blocs `data-coverage-yield-unknown` (RouterLink `{ name: 'ledger', query: { tab: 'mining' } }`, rien listé), `data-coverage-measuring`, `data-coverage-unknown` (prioritaires sur le rendement).
- Clés i18n attendues (fr + en) : `miningOperation.stockpileCoverage.{title,noDeficit,yieldUnknown,measuring,unknown}`.
- Vue : chargement de la couverture seulement pour un participant accepté et une opération `closing` ou `completed` ; rechargement sur `quantity_corrected` (via `load()`).
